瀏覽器保存、清除與跨裝置限制實測

確認測驗與修復資料只保存在目前瀏覽器，並驗證清除功能與共用裝置風險提示。

LoveTypes 內容編輯團隊 · 實測與更新：2026-08-01 · 內容與安全方法 · 回報無法重現

LoveTypes 不要求帳號，測驗結果與修復表使用 localStorage。這次測試直接檢查保存鍵、重新整理、清除按鈕、無痕視窗與另一個瀏覽器，確認資料不會自動同步。公開報告不揭露任何真實作答內容，只描述技術行為。

測試環境

  • macOS 26.5.2；Google Chrome 150.0.7871.187
  • 桌面 1440×900；手機 360×800（個別報告另列額外尺寸）
  • Build 49b06986d371；時區 Asia/Taipei (UTC+8)
  • Chromium 一般視窗與無痕視窗
  • 第二個獨立瀏覽器內容區
  • 瀏覽器開發者工具 Application 面板
  • 不使用帳號、Cookie 或遠端資料庫

固定輸入與預期

測驗 fixture 使用 W,T,G,S,P 重複三輪；修復表測試字串為 LT-LOCAL-ONLY-0731。檢查鍵包含 lovetypes:zh:quiz-result、頁面路徑版本的 quiz-result，以及 repair-plan 對應欄位。第二內容區與無痕視窗不先造訪本站。

重現步驟

  1. 完成測驗並填寫一個修復欄位。
  2. 重新整理，確認目前瀏覽器仍能讀取。
  3. 按清除結果與清除工作表，再檢查保存鍵。
  4. 開啟無痕視窗及第二瀏覽器，確認沒有同步資料。

原始觀察紀錄

一般視窗完成後重新整理仍可讀回結果與測試字串。依序按清除結果和清除工作表後，相關鍵不存在，頁面回到未填狀態。無痕視窗、第二瀏覽器內容區與另一個 Chrome profile 均未出現測試字串；Network 面板沒有發現把作答內容送往 LoveTypes API 的請求。

localStorage 是來源相同且以瀏覽器內容區隔保存的用戶端儲存，不等於加密保險箱。共用同一個系統帳號與瀏覽器 profile 的下一位使用者可能看見尚未清除的內容；瀏覽器擴充功能、裝置管理或備份也可能有額外存取能力。因此頁面同時提供清除控制與共用裝置提醒，不宣稱資料絕對不會離開裝置。

通過與失敗判準

驗收條件是一般視窗可以依產品承諾保存與清除、無痕和獨立內容區不自動取得資料、清除後 DOM 與保存鍵都沒有辨識字串。只清空畫面但鍵仍存在，或任何作答內容出現在本站網路請求中，都視為隱私失敗。

修正後如何重測

重測先用唯一辨識字串避免誤判，再同時檢查 Application 與 Network。清除後重新整理兩次，搜尋頁面來源、localStorage、sessionStorage、Cookie 與請求內容。瀏覽器政策可能改變儲存行為，因此 Chrome 主版本更新、保存鍵改名或新增分析服務時，都要重新核對並更新隱私說明。

證據保存範圍

證據保存包含清除前後畫面與保存鍵狀態；公開截圖使用測試字串，不含真人作答、姓名、聯絡方式或裝置識別資訊。

本次發現的問題

共用裝置上的下一位使用者可能看到尚未清除的結果；只寫「保存在本機」不足以說明這個風險。

已採取的修正

測驗、修復與隱私頁加入共用裝置提醒，並維持容易找到的清除控制。

尚未涵蓋與限制

瀏覽器擴充功能、備份軟體與裝置管理政策不在本站控制範圍；使用者仍應依自己的裝置風險決定是否保存。

報告性質與修訂

這是 LoveTypes 自有產品的工程與內容實測，不是受試者研究、臨床驗證或關係成效證明。頁面版本或測試條件改變時，必須重新執行後才能更新結論。
